# 门易修 GEO 优化行动方案

> 目标：让枣强、衡水附近有卷帘门维修需求的人，在豆包、千问、DeepSeek 等 AI 中提问时，能够看到门易修的服务范围和正确联系电话。

当前营业执照正在办理。办理期间先推进网站、内容、案例和监测；需要营业执照或企业资质的地图认领、企业认证和商户实体建设，统一放到执照办结后执行。

### 源码与发布约定

所有网站改动在 `website/zq-menyixiu-web` 子模块内完成：

```text
修改源码或内容
→ 在子模块运行 npm run build
→ 提交并推送子模块
→ Vercel 自动发布
→ 检查线上页面、robots 和 sitemap
→ 向百度提交新增 URL
```

GEO 文档只记录目标、动作和结果；具体网站实现以子模块源码为准。

## 二、核心目标

北极星指标：

> **每周来自 AI 的有效本地维修询盘数。**

有效询盘需同时满足：

- 客户明确来自 AI；
- 客户位于实际服务区域；
- 客户有真实卷帘门维修需求。

最终要形成：

```text
网站可抓取
→ 高意图问题有答案
→ 真实案例可验证
→ AI 结果可监测
→ 商户实体可确认
→ 询盘来源可追溯
```

## 三、阶段性目标

|---|---|---|---|

|阶段二：内容覆盖|营业执照办理期间|补齐独立服务页、地区页和案例页|新增页面进入 sitemap，部署后可访问并提交百度|

## 四、目标的关键动作

### 阶段一：解决百度未收录

**目标：**确认百度能发现、访问和读取当前站点，并找到尚未进入索引的具体环节。

关键动作：

1. 登录[百度搜索资源平台](https://ziyuan.baidu.com/site/index)，确认添加的是 `https://menyixiu.cn/`，且当前账号的站点验证仍然有效。
2. 核对平台要求的验证文件或 HTML 标签与线上版本一致。源码目前保留两份验证文件，页面使用 `codeva-aJGTvIXgvj`，以平台当前显示的验证码为准。
3. 提交 `https://menyixiu.cn/sitemap.xml`，并通过普通收录提交当前 9 个 URL。提交只能加快发现，不能保证收录。
4. 对首页、`/cases` 和一个核心 FAQ 执行抓取诊断，确认百度蜘蛛能读取：

```text
门易修
枣强卷帘门维修
联系电话
营业时间
实际服务区域
遥控器、控制器、电机、限位维修
```

5. 检查抓取频次、抓取异常、索引量和 robots 工具中的实际记录。
6. 在 Vercel 可用日志范围内检查是否出现 Baiduspider 访问。
7. 每次发布新页面后，只提交新增的高质量 URL，避免反复提交相同地址。

验收标准：

- 百度资源平台验证状态正常；
- 首页、案例页和 FAQ 抓取诊断成功；
- 百度蜘蛛看到的标题、正文、电话和服务区域正确；
- 平台开始出现抓取记录，索引量由 0 开始增长；
- 若仍未收录，能够明确是“未抓取、抓取失败、已抓取未索引”中的哪一种。

如持续抓取失败，先排查网络、DNS、robots 和 Vercel 访问情况；如已抓取但未索引，继续补充原创本地内容，不重复提交低价值页面。

### 阶段二：覆盖高意图问题

**目标：**让网站直接回答本地客户最可能提出的维修问题。

当前已有首页、案例列表页和 6 个故障 FAQ，但缺少独立服务页、地区页和案例详情页。

关键动作：

1. 首页直接说明服务区域、可维修故障、联系电话和营业时间。
2. 保留并持续更新现有 6 个 FAQ。
3. 下一批建立：

|页面类型|建议数量|重点内容|
|---|---:|---|
|服务页|3|卷帘门维修、遥控器／控制器、电机／限位|
|地区页|2～4|只写真实能够上门的区域|
|案例详情页|至少 3 个|一个真实案例对应一个独立 URL 和明确故障|

4. 每个故障或服务页回答：

```text
故障表现｜常见原因｜安全自查｜禁止操作
维修方法｜是否换件｜服务区域｜联系方式｜相关案例
```

5. 每个案例记录：

```text
日期｜区域｜门的类型｜故障表现｜检查过程
实际原因｜维修方法｜更换配件｜前后照片｜安全提醒
```

6. 将高质量抖音维修视频转成网页，补充文字稿、处理过程、图片、服务区域和电话。
7. 客户地址只写到乡镇、街道或大致区域，不公开隐私。
8. FAQ 内容继续放在 `content/faq/`；服务、地区和案例详情需要建立相应路由，并确保进入 `src/app/sitemap.js` 生成的 sitemap。
9. 每次发布后检查新 URL 的 200 状态、canonical 和 sitemap，再提交百度。

验收标准：

- sitemap 从当前 9 个 URL 增长到 15 个以上；
- 核心故障均有明确答案；
- 每页包含真实服务区域和联系方式；
- 至少有 3 个独立案例详情页，后续逐步累计到 10 个以上。

### 阶段三：建立 AI 监测与询盘归因

**目标：**知道门易修是否出现、从哪里出现、哪些结果带来客户。

关键动作：

1. 固定测试豆包、千问、DeepSeek 和 Kimi。
2. Prompt 分为四类：

|类型|示例|
|---|---|
|本地需求|枣强哪里有修卷帘门的？|
|故障需求|卷帘门只能下降不能上升怎么办？|
|价格／紧急需求|枣强修卷帘门多少钱？|
|品牌验证|门易修是做什么的？|

3. 重点测试非品牌问题，不主动在问题中写“门易修”。
4. 豆包核心问题重复测试，避免用一次结果下结论。
5. 保存平台、日期、Prompt、完整回答、引用链接、电话、出现位置和截图。
6. 分开记录是否登录、是否联网、是否开启定位和用户所在城市。

接到 AI 询盘时询问：

> 方便发一下您当时怎么问、AI 怎么回答的截图吗？我想确认电话和服务信息是否准确。

同时记录客户地区、来源平台、引用页面和最终是否成交。

验收标准：

- 有一组固定测试问题；
- 每次测试条件和结果可追溯；
- AI 询盘能够定位到平台、问题和引用来源；
- 能识别真正带来询盘的页面与问法。

### 阶段四：营业执照办结后统一本地商户实体

**目标：**让网站、抖音和地图能够被识别为同一个真实本地商户。

先确定唯一版本：

```text
商户名称
主营业务
实际服务区域
联系电话
营业时间
真实经营或服务地址
网站和抖音账号
```

关键动作：

1. 根据平台规则，用营业执照完成百度地图、高德地图等商户认领或认证。
2. 统一网站、抖音、地图中的名称、电话、地址、营业时间和服务范围。
3. 抖音条件允许时完成企业认证，关联真实 POI。
4. 上传真实维修、工具、车辆或经营图片。
5. 制作“门易修是谁、服务哪里、如何联系”的置顶内容。
6. 复核 `src/app/layout.js` 中现有的 `LocalBusiness`，再按注册信息补充或调整 `HomeAndConstructionBusiness`、`Service`。
7. `sameAs` 只关联真实、可访问的抖音和地图主页。

验收标准：

- 搜索“门易修”时，各平台信息没有冲突；
- 名称、电话、地址和服务区域保持一致；
- 结构化数据与页面展示完全一致；
- 不使用虚构门店、评价、星级或经营数据。

### 阶段五：根据结果持续优化

**目标：**把偶然曝光变成稳定、可归因的本地询盘。

每轮只优化一类变量，例如：

```text
真实案例
价格说明
服务区域
故障判断流程
维修前后图片
标题和首屏答案
```

观察两轮测试后再决定是否扩大。有效则应用到相似页面，无效则停止并记录结论。

重点加强：

- 最容易出现门易修的 5～10 个问题；
- 真正带来询盘的故障和地区；
- 被 AI 引用过的页面；
- 电话错误或信息不一致的来源。

不要同时大改所有页面，否则无法判断哪项动作有效。

## 五、核心衡量指标

|指标|计算方法|
|---|---|
|品牌提及率|非品牌测试中出现门易修的回答数 ÷ 非品牌回答总数|
|联系方式正确率|电话正确的回答数 ÷ 出现门易修的回答数|
|官网引用率|引用 `menyixiu.cn` 的回答数 ÷ 回答总数|
|前三推荐率|门易修进入前三的回答数 ÷ 推荐类回答数|
|AI 有效询盘|来自 AI、位于服务区域且有真实维修需求的客户数|

真正需要回答的问题是：

> 用户没有听过门易修，只提出本地维修需求时，AI 是否会主动推荐门易修，并给出正确电话？

最终目标不是让 AI “认识一个网站”，而是建立一个可抓取、可验证、可联系、持续有真实证据的本地服务实体。
