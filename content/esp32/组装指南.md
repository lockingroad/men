# ESP32-S3 + CC1101 433MHz 组装指南

整理日期：2026-11-03。配套文档：[购买清单](购买清单.md)。

本指南对应 **已焊排针的 ESP32-S3 开发板 + 亿佰特 E07-M1101D-SMA 直插模块 + 配套433MHz天线**，用母对母杜邦线组装，复用手机Type-C数据线和USB充电头。

**接线依据厂家资料整理，尚未做实物验证。下面的GPIO分配是本项目建议方案，烧录的固件必须使用同一配置。本文没有提供可直接烧录的成品固件。**

## 1. 组装前确认

- 两块板均已焊好排针，杜邦线可以直接插接；CC1101型号是 **E07-M1101D-SMA**。
- ESP32-S3板上能找到 `3V3`、`GND` 和 `GPIO9～GPIO14` 对应的标识，且这些GPIO未被板载其他外设占用。42针和44针开发板的排布可能不同，以实物丝印及该板引脚图为准。
- 现有Type-C线支持数据传输，既能接电脑烧录，也能接充电头供电。
- 组装时放在绝缘桌面上；插拔杜邦线前拔掉USB电源。

如果拿到的是原来的 **E07-433M20S** 贴片模块，不使用本文的模块引脚编号；它还需要转接或代焊，以及TX_EN/RX_EN控制。对应说明见 [购买清单](购买清单.md)。

## 2. 供电方式

```text
手机 ── BLE蓝牙 ──> ESP32-S3 ── SPI/控制线 ──> CC1101 ──> 433MHz天线
                       ↑                        ↑
现有USB充电头 ── Type-C线 ──> 开发板USB口       开发板3V3、GND
```

充电头使用5V输出，建议额定输出至少1A；已有5V/2A充电头也可以。**5V只进入开发板USB口，CC1101的VCC接开发板3V3，不接5V。**

E07-M1101D-SMA厂家标注供电范围为1.8～3.6V，典型3.3V；10dBm发射时典型电流约29mA。开发板的3.3V电源需在自身运行之外留出外设余量，本方案建议至少约50mA。第三方板子的供电能力应看卖家电路说明，不能直接套用乐鑫参考板参数。[模块电气参数](https://www.ebyte.com/product/57.html)

烧录时由电脑USB供电，日常运行再换充电头；首版只使用这一个USB供电入口，不另外向5V或3V3排针输入电源。手机负责蓝牙控制，不要求手机本身给开发板供电。

## 3. 接线表

先断电、装好配套天线，再接线。**ESP32这一列是GPIO编号，不是“从上往下数第几个针脚”。** CC1101编号须按厂家引脚图辨认，不能凭天线朝向猜。

| E07-M1101D-SMA引脚 | 接ESP32-S3 | 作用 |
| --- | --- | --- |
| 1：GND | GND | 共地 |
| 2：VCC | **3V3** | 3.3V供电 |
| 3：GDO0 | GPIO9 | 射频数据／事件信号，功能由固件配置 |
| 4：CSN | GPIO10 | SPI片选 |
| 5：SCK | GPIO12 | SPI时钟 |
| 6：MOSI | GPIO11 | ESP32向CC1101发送数据 |
| 7：MISO/GDO1 | GPIO13 | CC1101向ESP32返回数据 |
| 8：GDO2 | GPIO14 | 备用事件信号，是否使用取决于固件 |

厂家另外列出的9、10号也是GND接地点；如实物引出这些接地点，按厂家图接同一GND。它们不是ESP32的GPIO9、GPIO10，不能接到上表的信号线上。

模块侧定义依据 [亿佰特引脚表与引脚图](https://www.ebyte.com/product/57.html)。ESP32侧的GPIO分配为本项目选择，不是所有CC1101固件的默认值；若采用已有固件，需核对并修改固件配置或对应调整接线。

建议保留的固件配置记录：

```text
CC1101_SCK   = 12
CC1101_MISO  = 13
CC1101_MOSI  = 11
CC1101_CSN   = 10
CC1101_GDO0  = 9
CC1101_GDO2  = 14
```

杜邦线用约10cm短线，逐根核对。板子之间使用相同名称的SPI信号连接，MOSI/MISO不交叉接成串口TX/RX。布线和固定件尽量避开ESP32的板载天线区域。

## 4. 首次上电与验证顺序

1. **先单独测试ESP32-S3。** 暂不连接CC1101，用数据线接电脑；确认开发板供电正常、能够识别烧录接口。如果板上有两个Type-C口，按丝印和该板说明选择下载口。
2. **确认3.3V电源。** 核对开发板外设供电能力；有万用表时，测量3V3对GND应约为3.3V。随后拔掉USB，再按表接CC1101。
3. **再次核对接线后上电。** 确保VCC未接5V，排针没有插错一格，天线已连接。若出现明显发热或反复重启，断电检查供电、短路和插线位置。
4. **先验证SPI通信。** 使用配置匹配的诊断固件读取CC1101的芯片识别／版本寄存器；持续读到全0或全1时先检查接线、片选和供电。仅指示灯亮不能证明CC1101已正常工作。
5. **再验证BLE连接。** 固件需要主动广播并实现控制服务；手机系统蓝牙列表里看不到它，不一定是硬件故障。应使用与固件服务匹配的App或BLE调试客户端测试。
6. **最后做遥控协议适配。** 确认自家控制器的实际频点、调制与编码，再实现控制指令。433MHz相同不代表协议相同；滚动码也不能假设录制后直接重放即可控制。

硬件装好后，还需要开发或选定匹配的 **BLE＋CC1101固件**。至少要明确BLE服务与指令格式、上表GPIO配置，以及目标控制器协议，才能从手机完成开／停／关操作。本指南完成的是硬件连接准备，不代表卷帘门功能已经联调通过。

## 5. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 插充电头不亮，尤其是双头Type-C线 | 换现有USB-A转Type-C线测试；第三方板子的C-C供电实现可能不同 |
| 有电但电脑无法识别 | 数据线是否只有充电功能、是否接对下载口、USB串口驱动是否匹配该板芯片 |
| CC1101无法识别 | 3.3V与共地、CSN、MOSI/MISO、固件GPIO配置、杜邦线是否插错位 |
| 一发射就重启 | 供电余量、线材和接触；必要时再按购买清单增加独立3.3V电源 |
| 手机找不到设备 | 是否烧录BLE固件、是否开始广播、手机App是否有蓝牙权限 |
| BLE已连接但门不动作 | 射频参数、编码、控制器配对状态、天线；不能仅凭蓝牙连接成功判断射频控制成功 |
