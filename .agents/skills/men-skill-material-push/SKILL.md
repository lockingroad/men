# 门壹修素材存档与发布

用户明确调用 `$men-skill-material-push` 处理素材即授权本次归档、网站更新、两个仓库的常规 commit/push 和线上验收。自动匹配时以用户实际授权范围为准。用户限制为先存档、只改本地或仅审查时，遵循该范围。IndexNow 实际提交另依用户的相应授权。

## 归档与生成网页

1. 在主仓库读 `AGENTS.md`。先只读核对本次输入与已有档案，确认本地视频、完整口稿和用户给定的抖音来源各自是否可用。检查本地工作区和暂存区，记下已有改动。
2. 执行 [抖音作品归档](../men-skill-douyin-archive/SKILL.md)，先在本地保存可用输入。新素材缺项时交付作品 ID、归档位置和待补项，到此结束，整个分支可离线完成。给已归档作品补链接或小修时复用已有材料。
3. 具备本次所需发布输入并准备进入网站步骤时，再核对主仓库及独立 Web 子模块 `website/zq-menyixiu-web/` 的分支、remote 与工作状态，分别 fetch。按实际远端关系同步，保留刚归档的材料、其他本地变更及并发更新的索引记录；重新核实同一作品 ID。网页操作按主仓库 `docs/rules/playwright.md` 确认无窗口会话。
4. 执行 [制作与验证视频 FAQ](../men-skill-video-geo-faq/SKILL.md)。取得目标 slug、Web 子模块变更和本地验证结果。将实际 FAQ 路径回填作品说明及索引。仅补来源链接时，检查原存档、页面来源和结构化数据，沿用既有媒体与日期。

## 双仓库交付

1. 检查两个仓库差异与暂存，只纳入本次文件。排除构建输出、日志及浏览器资料。有其他任务的暂存时按本次路径提交，保留原有暂存状态。
2. 先在 Web 子模块 commit，再常规 push 到核实过的发布分支。确认该提交在远端可用后，主仓库再提交素材、作品说明、索引和更新后的子模块指针。本次有新归档的原片或原稿时，核实提交树确实含对应文件，原片校验值匹配后再 push。仅补来源时保持历史原片的 Git 跟踪状态。若原片超过远端限制，记录具体限制，完成其余可交付工作并报告存档完整性；迁往其他存储需用户授权。
3. 远端若前进，重新 fetch 并核对双方变更。先解决子模块历史，再更新主仓库指针，重新验证受影响内容后常规 push。保留双方有效内容，避免 force push。确认两个本地提交与各自远端目标分支同步。只有一个仓库变化时只提交有变化的一方，仍核对两仓状态。

## 线上验收

从站点配置核对域名和目标 URL，当前入口为 `https://menyixiu.cn/faq/<slug>`。检查返回的实际标题、正文或来源属于本次版本；核对首页、常见故障列表、相关服务页入口及 sitemap。新媒体须能在浏览器加载播放，图片可用；抖音来源须与本次输入及页面结构化数据一致。仅补来源链接时验证变更已出现在生成页及线上入口。

若部署仍返回旧版或错误，约每 20–30 秒复查，单次等待不超过 60 秒。约 5 分钟持续未更新时查可访问的部署状态或日志；只修复本次变更引入且获授权的问题。托管、域名或凭据变更需另有授权。线上版本仍不可确认时，报告已推送的提交、具体验收障碍和已查状态。

IndexNow 默认仅 dry-run。得到相应提交授权并确认线上为本次版本后，才实际提交本次相关 URL。最终给出素材位置、线上页面、两仓提交号和核实结果，明确线上是否已发布，以及 IndexNow 是预检还是实际提交。
