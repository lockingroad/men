# 门壹修抖音作品归档

从主仓库读 `AGENTS.md`、`content/INDEX.md` 与已有作品说明。检查本次附件、对话和指定目录，复用已经提供的材料。只要求存档时，完成本地归档即交付；网站变更、提交和推送由用户另行指定。完整发布由 [$men-skill-material-push](../men-skill-material-push/SKILL.md) 接续。

## 定位作品

先在索引找稳定作品 ID，用指定目录、抖音作品链接或作品号、已有原片 SHA-256 和原稿内容交叉核对。不同版本可能同题，只有标题相似时保留区分，身份仍有歧义再询问。匹配已有作品就原位补齐；新作品遵循索引现有 ID 约定，优先用户指定目录，未指定时用简短稳定的主题目录。用实际内容确认哪个文件保存口稿、哪个文件保存复盘，保留历史文件名与原有链接。

仅补来源时先比对已有记录。该作品已记有相同链接且本次没有其他补件，直接回复「来源已记录」，工作区保持零改动。补入新链接时只更新对应来源和实际受影响的索引指针，沿用旧原稿、视频、日期与 Git 忽略规则。

## 存入主仓库

1. 在 `content/<素材目录>/` 保存可用材料。已收到的口稿完整保留原文与段落，把编辑稿、网站文案及核实说明另列。局部口稿标明缺段。记录用户给定的抖音原链接，创作者后台入口另列。把可核实的抖音发布日期、归档日期、指标快照日期分别记录；未知项留空，有数据时标明日期和来源。
2. 复制原片前比较目标是否存在。同名同 SHA-256 复用；同名异内容另存并记录版本。保留用户原件，比对源件与归档副本的 SHA-256，用 `ffprobe` 记录时长、画面尺寸、编码和字节数。素材说明使用可从主仓库定位的路径。本次新归档的原片若被忽略，才为其添加同目录精确的 `.gitignore` 例外，核查 `git check-ignore` 和 `git status`；区分「仅在本机」「允许跟踪」与「已进入提交」。在被授权提交时，验证提交中确有原稿及匹配校验值的原片。遇远端大小限制，保留本地原件并报告具体限制；迁往外部存储须另有授权。
3. 新建作品或索引字段发生变化时，更新 `content/INDEX.md` 里该 ID 的一条记录。沿用现有列和相对链接，指向权威稿件、原片或其记录、复盘及已经确认的 FAQ。FAQ 的 slug 和原有 ID 在后续补件时沿用。索引作检索入口，指标、校验值与完整原稿保存在作品目录，避免多处维护全文。编辑前重读当前索引，保留其他作品的修改。
4. 仅有部分材料也可在本地建档。列出已收项目、待补的视频／链接／完整口稿及实际 Git 状态。补件时更新同一 ID 和目录。用户只补链接时保留原稿、原始日期与原视频，不重转媒体。三项齐备后才具备新素材网站发布所需的输入。

交付时给出作品 ID、素材说明和索引位置，注明仍待补的输入及原片的恢复位置。完整实例见主仓库 `content/appv1/appv1.md`。
