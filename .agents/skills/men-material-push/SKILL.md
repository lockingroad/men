# 门壹修素材存档与发布

负责从素材到线上可访问页面的完整交付。面向网站访客写简洁说明，保留作者原稿；不要只完成本地修改或 Git push 就宣称发布成功。

## 项目与依赖

- 主仓库：当前 `men` 项目，素材位于 `content/`。
- Web 子模块：`website/zq-menyixiu-web`，是独立 Git 仓库。
- 线上站点：`https://menyixiu.cn`；执行前与当前网站配置核对。
- 首先读取项目 `AGENTS.md`。网页操作遵循 [Playwright 使用规则](../../../docs/rules/playwright.md)，确认当前会话使用无窗口模式，不接管用户日常浏览器。
- 内容模型、媒体转换和结构化数据沿用 [视频 FAQ 技能](../zq-menyixiu-video-geo-faq/SKILL.md) 与其 [网站参考](../zq-menyixiu-video-geo-faq/references/site.md)。本技能补充素材存档、双仓库交付和线上验收流程，不另建内容模型。

## 素材与授权

执行前定位三项输入：可读取的本地视频、用户提供的抖音链接、完整口稿文字。结合本次附件、对话与指定素材目录查找，不要求用户重复提供已经给过的内容。

新素材发布必须三项齐全，缺一不可。缺项时先说明缺少哪项并请求补充；可继续核对已有文件和仓库，但不把不完整的新素材提交发布，不编造视频、来源链接或原稿。对已存档内容的补链接或小幅修订，直接复用项目内已有视频与原稿。

使用用户指定的素材文件夹名，如 `appv1`，归档到 `content/appv1/`；未指定时采用简短稳定的主题名。已有内容优先原位补充，避免同一视频因补链接而新建另一篇页面。

用户明确调用 `$men-material-push` 处理素材，即按完整流程执行存档、网站更新、两个仓库的常规 commit/push 及线上验收；不需要另外再说一次“发布”，也不再重复询问是否提交。自动匹配技能时，以用户实际授权范围为准。仅咨询、审查、创建技能本身或明确“先别发布”，不自动发布业务内容。

## 存档

1. 先检查两个仓库的分支、remote、工作区与暂存区，记录本次改动范围。主仓库与子模块分别 fetch，基于实际远端关系同步，保留无关本地改动。
2. 将原视频复制到 `content/<folder>/`，不移动或覆盖用户原件；比较源文件和副本的 SHA-256。已有同名文件先比对，不能盲目覆盖。
3. 在 `<folder>.md` 保存完整原稿、抖音链接、归档日期、视频文件名、校验值和网站文章路径。原文与网站整理说明分开；不要用润色稿冒充原稿。
4. 用 `ffprobe` 记录真实时长、尺寸、编码和大小。归档日期不充当抖音发布日期；未知日期和播放、点赞、收藏数据留空，不推测。
5. 默认根目录忽略视频，但此流程要求原视频也可从 Git 恢复。对本次视频使用素材目录内的精确 `.gitignore` 例外，例如 `!source.mp4`，不要全局放开所有视频。暂存后确认原视频确实进入提交。若文件超出远端限制，说明具体限制并先完成其余工作；未经用户同意不擅自迁往外部存储，也不宣称存档已推送完整。

## 网站内容

- 通读口稿、探测视频并查看代表性画面。原稿存档不改写，网站正文单独润色；画面只支持其实际展示的内容。
- 标题直接对应访客问题，开头先回答“能不能、怎么处理”。正文保留必要原因与实用建议，删除大段制作过程、原稿辩解和重复提醒。通常短段落加少量问答即可，不为凑结构拉长页面。
- 将未经核实的绝对结论、固定报价和时效承诺改成有条件的说明。技术判断不确定时核对官方资料，不把广告预告写成现成服务；服务口径使用网站统一配置。
- 根据画面选择封面和少量关键帧，使用已有 `prepare_video_assets.py` 生成浏览器兼容 MP4。尺寸和时长以成品探测结果填写，不能把 HEVC 原片改扩展名充当转码。
- 新 FAQ 放在 Web 的 `content/faq/<slug>.md`，slug 用稳定的小写英文短横线形式。使用 `sourceUrl` 保存抖音链接，让页面呈现来源入口并生成 `Article.citation`、`VideoObject.sameAs`；`video.src` 指向网站 MP4。
- 纯动画或屏幕演示可填写 `video.label: "原理讲解"`，不要误标为实拍。其余 frontmatter 沿用网站模型，不伪造公开表现数据。
- 加入首页 `HOME_FAQ_SLUGS` 和“常见故障”列表；通过相关服务的 `relatedFaqs` 或现有入口关联新页。只给真正相关的旧 FAQ 补双向链接，并更新实际改动页面的日期。保留仍有效的旧入口与稳定 URL。
- 用户后来仅补抖音链接时，只更新原存档、`sourceUrl` 和相关校验；不重转视频、不改原始日期、不重写无关内容。

媒体脚本位于主仓库，输出目录位于 Web 子模块。以下命令从主仓库根目录运行，执行前替换占位值，时间点应根据本次视频实际选择；不要照依赖技能的通用示例输出到主仓库 `public/`：

```bash
python3 .agents/skills/zq-menyixiu-video-geo-faq/scripts/prepare_video_assets.py \
  --input "content/<folder>/<source>.mp4" \
  --public-dir "$PWD/website/zq-menyixiu-web/public" \
  --slug "<slug>" \
  --poster-at "<seconds>" \
  --frame "<name>=<seconds>"
```

## 本地验证

在 Web 目录执行现有要求：

```bash
npm test
npm run build
npm run indexnow:dry
git diff --check
```

只在媒体、链接或内容边界需要保障时补充有意义的校验；调整受本次变更影响的既有断言，不为文案小修另造测试体系。

检查生成 HTML：标题与直答可见、来源链接准确、JSON-LD 可解析、问答与页面一致、视频 URL/封面/日期/时长正确、sitemap 含新地址及真实日期。

新增页面或布局变化时，用无窗口浏览器检查 1280×720 与 390×844：视频可加载并播放、图片完整、没有横向溢出、底部拨号栏不遮挡必要内容、没有页面错误。仅补链接时检查生成页面和线上来源入口即可，不重复无关的媒体处理。

## 双仓库提交与推送

1. 检查差异，只暂存本次网站文件；不提交 `.next`、日志、浏览器登录信息或其他任务的改动。
2. Web 仓库先 commit，再向核实过的目标分支 push。默认沿用项目已建立的发布分支；不假定当前分支一定是 `main`，不 force push。
3. 子模块提交在远端可用后，主仓库提交本次素材、原视频、归档说明和更新后的子模块指针，再 push。用户已有无关暂存内容时，用限定路径的提交方式保留其暂存状态，不直接 `git commit -a` 或提交全部暂存内容。
4. 若远端前进，重新 fetch、检查差异并解决冲突，保留双方有效内容。先处理子模块本身的历史，再更新主仓库指针；不要随意选一个 gitlink 覆盖另一个。重新验证受影响的内容后重试常规 push。
5. 确认两个本地提交都与相应远端分支同步。若本次只有一个仓库实际变化，不制造空提交，但仍核对两仓库状态。

## 线上验收

推送触发既有发布流程后，核对 `https://menyixiu.cn/faq/<slug>` 的实际内容，不能以 push 成功、HTTP 200 或构建结束单独代表上线成功。

- 返回成功状态，且标题、正文或来源链接已经是本次版本。
- 首页和“常见故障”列表包含可访问的文章入口；相关服务链接正常。
- 新视频可在浏览器加载并播放，关键图片返回成功，sitemap 出现文章地址。
- 抖音入口与用户给定 URL 一致，结构化数据中的来源也一致。

部署期间可能暂时返回旧页面或错误。每隔约20–30秒检查一次，单次等待不超过60秒；约5分钟仍未生效或出现持续错误时停止盲目轮询，读取可访问的既有部署日志或状态并定位问题。只修复本次变更引起且已授权的问题；不擅自重配托管、域名或凭据。无法修复时如实报告提交已推送、发布尚未确认及具体阻碍，不写“稍后刷新就好”代替验收。

IndexNow 默认仅 dry-run。只有得到相应提交授权且线上已经更新后，才实际提交本次相关 URL；交付时区分预检与真正提交，不把它当作部署条件。
